# AtlasQuarry 運用手順書

## 通常リリース

1. `main` のCIが成功していることを確認する。
2. リリース対象のコミットをローカルで取得する。
3. `docker build -t atlasquarry:latest .` を実行する。
4. `scripts/deploy.sh` を実行する。SSHホストは `DEPLOY_HOST`、リモートディレクトリは `REMOTE_DIR` で変更できる。
5. `https://atlasquarry.duckdns.org/api/health` が `status=ok` を返し、ログイン画面が表示されることを確認する。
6. 変更した主要導線（ログイン、今日、要望、タスク、設定）をブラウザで確認する。

## 監視

```bash
COMPOSE_FILE=docker/compose.yml scripts/healthcheck.sh
```

外部監視は `/api/health` を1分間隔で確認し、HTTP 503またはタイムアウトを通知対象にする。このエンドポイントは認証不要だが、DB接続状態以外の内部情報は返さない。

## バックアップ

```bash
scripts/backup-cron.sh
```

日次・週次・月次で保存先を分け、世代数を超えた古いファイルを削除する。バックアップ後は必ずアーカイブの検証を行う。

```bash
scripts/verify-backup.sh backups/atlasquarry-YYYYmmdd-HHMMSS.pgc \
  backups/atlasquarry-attachments-YYYYmmdd-HHMMSS.tar.gz
```

## 復元

復元は本番へ直接実行せず、先に `docker/compose.dev.yml` の別DBで検証する。

```bash
COMPOSE_FILE=docker/compose.dev.yml COMPOSE_PROJECT_NAME=atlasquarry-dev \
  scripts/restore.sh backups/atlasquarry-YYYYmmdd-HHMMSS.pgc
```

`restore.sh` は既存DBを上書きするため、実行時に `yes` を明示しない限り開始しない。復元後は `scripts/healthcheck.sh`、ログイン、データ件数、添付ファイルを確認する。

別DBへ復元検証する場合は `RESTORE_DB=<検証用DB名>` を指定する。本番DB名を変更せずに、復元結果を隔離できる。

## 障害対応

- アプリだけ停止: `docker compose -f docker/compose.yml restart app`
- DBの状態確認: `docker compose -f docker/compose.yml ps db` と `docker compose -f docker/compose.yml logs db --tail 100`
- アプリの状態確認: `docker compose -f docker/compose.yml logs app --tail 100`
- 直前イメージへ戻す場合は、デプロイ前に保存したDockerイメージタグを再起動する。DBの破壊的操作は行わない。
